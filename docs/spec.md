# Safe Trip 기획서

---

## 1. 서비스 설명

여행지별 실제 사기 경험을 바탕으로, 그 지역에서 어떤 사기가 얼마나 발생하는지 한눈에 볼 수 있는 서비스입니다.

---

## 2. 문제 정의

여행은 즐거운 경험을 위해 떠나는 것입니다. 하지만 현지에서 사기를 당하면 그 여행 전체가 망가질 수 있습니다.

"내가 가는 곳에서 어떤 사기를 조심해야 하지?"라는 질문에 빠르게 답해주는 곳이 없습니다. 정보는 인터넷에 충분히 있지만, 목적지에 맞는 정보를 출발 전에 한눈에 파악하기 어렵습니다.

Safe Trip은 실제 여행자들의 경험을 수집하고 집계해서, 목적지의 사기 현황을 바로 볼 수 있게 합니다.

---

## 3. 타겟 사용자

여행을 떠나는 모든 사람들, 그리고 자신의 경험을 공유하고 싶은 사람.

---

## 4. 해결 방식

### 데이터 수집

Reddit의 여행 관련 커뮤니티(ex: r/travel, r/scams, r/solotravel, r/backpacking)에서 실제 여행자들이 올린 사기 경험담을 자동으로 수집합니다. 수집된 원문은 OpenAI를 통해 두 단계로 처리됩니다. 먼저 여행 사기와 관련 있는 글인지 분류하고, 관련 있는 글에서 사기 유형, 발생 위치, 피해 상황 같은 정보를 구조화된 형태로 추출합니다. 이 과정을 매일 자동으로 실행해서 최신 데이터를 유지합니다.

사용자가 직접 경험을 제보할 수도 있습니다. Reddit 데이터가 부족한 지역을 보완하고, 서비스를 직접 사용하는 여행자들의 최신 경험이 반영됩니다.

### 정보 제공

수집된 데이터를 두 가지 형태로 제공합니다.

**목적지 위험도 (Risk Score)**
도시나 국가별로 보고된 사기 건수를 집계하고, 전체 데이터 분포 기준으로 상위 20%는 HIGH, 중간 60%는 MEDIUM, 하위 20%는 LOW로 표시합니다. 예: "바르셀로나 🔴 HIGH"

**트렌드**
전체 데이터를 기준으로 어떤 사기 유형이 많이 발생하는지, 최근 들어 늘고 있는 유형은 무엇인지 통계로 보여줍니다.

---

## 5. 차별화 (Why Us)

개별 경험담이 아닌 집계된 데이터를 목적지 기준으로 제공합니다. "방콕에서 어떤 사기가 얼마나 발생하는지"를 수백 건의 경험을 바탕으로 집계해서 보여주는 것이 Safe Trip의 핵심입니다.

## 7. 고려 사항

단일 커뮤니티(Reddit)에 의존하는 구조라 Reddit 사용자층이 자주 찾는 여행지에 데이터가 집중됩니다. 그렇지 않은 지역은 데이터가 부족할 수밖에 없으며, 이런 경우 "아직 데이터가 부족합니다"라고 명시합니다. 장기적으로는 Reddit API 정책 변경에 따른 데이터 소스 의존성 리스크도 존재합니다.

## 8. 향후 방향 (Post-MVP)

- 북마크 (관심 리포트 저장)

- 상황 기반 패턴 (공항·교통 등 특정 상황에서의 사기 집계로 좀 더 사용자를 위한 기능으로 확장)
- 데이터 소스 확장

## 9. 기술 선택 (Why This Stack)

| 영역 | 기술 | 역할 |
|------|------|------|
| ETL | Python + OpenAI Batch API | Reddit 수집 → 분류 → 파싱 → 적재 (일일 자동화) |
| 비정형 저장 | MongoDB | Reddit 원문 및 파싱 중간 데이터 저장 |
| 구조화 저장 | MySQL | 집계·서빙용 최종 데이터 저장 |
| API | Spring Boot (Java 17) | REST API 제공 |
| Frontend | Vue 3 + Leaflet | 지도 기반 인터랙티브 UI |
| 인프라 | AWS EC2 + Docker + GitHub Actions | 배포 및 CI/CD |
